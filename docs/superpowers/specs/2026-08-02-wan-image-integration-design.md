# 万相对话式生图接入设计

## 目标

将现有的商品素材工作台原型从本地占位图生成改为真实调用阿里云百炼万相 2.7 图像生成服务。点击“发送”后，页面生成文生图或基于上传/引用图的图像编辑结果，并继续支持版本、草稿、引用、保存和下载。

## 已确认的产品决定

- 运行方式：Node.js 18+ 本地服务，同时提供静态页面和 API。
- 模型：`wan2.7-image`。
- 默认生成数量：1 张。
- 用户可在快捷参数中明确选择 1–4 张；该数值原样传递给模型的 `n` 参数。
- 生成结果需要在本地保存，不能依赖万相最多保留 24 小时的临时链接。
- API Key 必须只存在于服务端环境变量；不写进网页、JavaScript、README 示例或版本控制。

## 方案选择

采用零依赖 Node HTTP 服务，而不是 Express。

理由：项目当前只有静态 HTML、CSS 和浏览器 JavaScript，且 Node 18 已具备 `fetch`、`node:test` 和文件系统能力。一个小型服务既能托管页面，又能代理模型请求、保存结果图片，不需要增加运行时依赖或构建步骤。

不采用浏览器直连百炼：会公开 API Key，并且不适合处理结果持久化。

## 架构

```text
浏览器 app.js
  │ POST /api/generate { prompt, images, count, size }
  ▼
Node server.mjs
  ├─ 校验请求与图片数量/大小
  ├─ 从 DASHSCOPE_API_KEY 读取密钥
  ├─ 调用万相原生图像生成接口
  ├─ 下载返回的临时 PNG 到 generated/
  └─ 返回本地 /generated/<id>.png URL
  ▼
万相 wan2.7-image
```

浏览器继续负责已有的项目、任务、提示词模板和版本元数据；服务端不保存用户项目数据。浏览器原有的 localStorage 状态将保存来自 `/generated/` 的本地图片 URL，使页面刷新后仍能展示已生成内容。

## 万相请求与响应

使用万相官方图像生成原生接口：

`POST https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`

用户提供的 `https://dashscope.aliyuncs.com/compatible-mode/v1` 是 OpenAI 兼容聊天入口；万相 2.7 图像生成文档指定上面的原生多模态生成接口，因此图像生成服务不通过兼容聊天入口调用。

请求模型为 `wan2.7-image`，并发送：

- `input.messages[0].role`: `user`
- `input.messages[0].content`: 合成提示词的文本，以及最多两张参考图（原图和引用图）
- `parameters.n`: 前端选择的 1–4
- `parameters.size`: 文生图时根据比例参数映射的像素尺寸；含参考图时使用 `1K`，让服务按参考图比例输出
- `parameters.watermark`: `false`
- `parameters.thinking_mode`: 文生图时为 `true`

万相图像 API 是单轮输入。当前产品的“对话式”体验通过保存每次用户指令和将选中的上一版图片作为下一次请求参考图来实现，而不向模型伪造多轮聊天历史。

服务端解析 `output.choices[].message.content[]` 内的图像 URL；每张图片下载后写入 `generated/`，再把本地路由返回给浏览器。万相临时 URL 和任务数据最多保留 24 小时，所以必须在生成完成时下载。

## 前端行为

### 发送

`sendMessage` 延续现有的表单校验和提示词合成逻辑。`runGeneration` 改为：

1. 设置状态为“排队中/生成中”，禁用发送按钮。
2. 组装文本提示词、当前图片和被引用图片，调用 `/api/generate`。
3. 根据响应中的图片数组创建真实草稿，保留现有版本、来源引用、模板快照和消息记录。
4. 成功后将任务设为成功；失败后将任务设为失败，并显示可安全公开的错误信息和重试按钮。
5. 无论成功或失败都重新启用发送按钮。

“重新生成”和“一键重试”必须重用最近一次有效的生成输入，而不是发送“重试生成”这类替代提示词。

### 数量与比例

快捷参数抽屉增加“生成数量”下拉框，取值为 1、2、3、4，默认 1。该值保存在任务参数中。

文生图会将已有比例选项映射为万相支持的像素尺寸。未填写比例时使用 `1024*1024`。图生图/引用调整不强制比例，因为万相按最后一张参考图的比例输出。

### 本地图片引用与下载

新生成图片在前端使用 `/generated/` URL。后续引用这类图片时，服务端仅允许读取自身 `generated/` 目录下的路径并转为 Data URL 后传给万相；不允许按用户传入的任意本地路径读取文件。

现有下载功能的文件扩展名改为 PNG，并下载真实图片。确认“高清成品”不再替换为占位 SVG，而是保留所选草稿图片。

## 安全与错误处理

- `DASHSCOPE_API_KEY` 只通过服务进程环境变量读取；服务器启动时若缺失则明确提示，API 返回不泄露密钥。
- `.env` 和 `generated/` 写入 `.gitignore`；提供不含密钥的 `.env.example`。
- API 仅允许 `POST /api/generate`，只服务同源浏览器。请求体设置安全上限，限制图片数量为 0–2、每张 Data URL 不超过 20 MB、`count` 为 1–4、提示词为非空且最多 5000 字符。
- 上游非 2xx、无图片、网络超时或下载失败均转换为可读错误；服务端记录请求 ID 和精简错误上下文，不记录 Authorization 头或完整 Data URL。
- 浏览器将错误写入任务消息，并使用最近一次成功组装的输入支持重试。

## 文件边界

| 文件 | 责任 |
| --- | --- |
| `server.mjs` | 静态文件服务、`/api/generate`、输入校验、万相调用、图片持久化、同源安全头 |
| `wan-client.mjs` | 纯粹构建万相载荷、调用上游、提取图像 URL、下载图片 |
| `app.js` | 生成数量状态和控件、请求本地 API、真实草稿/错误/重试处理、PNG 下载 |
| `index.html` | 生成数量控件 |
| `package.json` | 启动和测试脚本；不引入第三方依赖 |
| `.env.example` | `DASHSCOPE_API_KEY` 的空白示例 |
| `.gitignore` | 忽略 `.env` 与 `generated/` |
| `test/wan-client.test.mjs` | 万相载荷、数量校验和响应提取测试 |
| `test/server.test.mjs` | HTTP 接口校验和错误转换测试 |
| `README.md` | 安全配置、启动方式、模型与输出数量说明 |

## 测试与验收

自动化测试使用 Node 内置 `node:test`，不调用真实付费 API：

1. 未指定数量时请求 `n=1`。
2. 用户选择 2、3、4 时请求传递对应的 `n`。
3. 0、5、非整数、空提示词、非法图片输入被拒绝。
4. 文生图仅发送文本；图生图和引用调整按顺序发送图片与文本。
5. 正常万相响应中的一张或多张图片 URL 会转换为本地草稿 URL。
6. 万相错误、无图片响应、下载失败会安全转换为 API 错误。

手动验收：启动本地服务后，分别测试默认一张文生图、选择多张文生图、上传原图后的图生图、引用生成结果后的调整、错误提示、重试、保存素材库和 PNG 下载。真实 API 验证只在已在环境变量中配置新密钥且用户愿意承担调用费用时执行。

## 运维说明

需要在目标机器安装 Node.js 18 或更高版本。开发环境可使用 Codex 提供的 Node 运行时执行测试，但最终用户启动服务时仍需有可用的 Node 命令。
