# 版本链路与组图对话拆分设计（V5.0）

## 目标

1. **版本 = 修改分支**：选中版本后，草稿区展示该分支的浅层路径：`原图? → 直接引用图? → 当前结果`（方案 A，不串同轮未引用候选）。
2. **组图对话拆分**：一次多张结果在对话中拆成多条，每条可单独引用修改。
3. **同任务重传原图 = 新版本**：已有版本后再上传图片并发送，开新版本，不覆盖旧版本起点。

## 路径规则

对版本 `V`：

- 若有 `sourceImage` → 路径含「原图」（优先用版本自带 `sourceImage`，避免重传后冲掉旧版起点）
- 若 `V` 有父草稿（`parentDraftId` / `refImage`）且与原图不同 → 含该父图
- 最后含 `V` 的当前选中草稿（默认首张）

例：原图→图1 为 V1 → `[原图, 图1]`。

## 何时续写 / 何时新建版本

| 场景 | 结果 |
| --- | --- |
| 引用某版本 **tip（最新一张）** 再生成 | **续写同一版本**（如仍属 V1） |
| 引用 **非 tip**（同轮另一候选、更早步骤） | **新建版本**（如 V2） |
| 同任务 **已有版本后重新上传图片** 再发送 | **新建版本**（强制 create，清空瞬时引用） |
| 任务尚无版本时首次上传 | 记为任务原图，首轮成功后成为 V1 起点 |

续写时路径变长：`原图 → 上一步(旧 tip) → 结果(新图)`，版本条不新增。

版本展示名：`V{n}`。版本条仍列出各版本（及原图入口）；点击版本刷新草稿路径。

## 对话

- 成功后为每张草稿各推一条 `ai` 消息（`versionId` + `draftId` + 单元素 `drafts`）
- 每条旁有「引用修改」，引用该张
- 生成中占位按张数拆成多条骨架

## 非目标

- 不做完整祖先树展开（超过「原图+父+当前」）
- 不把同轮未引用候选并入路径
