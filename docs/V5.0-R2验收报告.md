## 不通过 / 仍不合理的点 + 改良方案

### 1. 步骤标签重复（P1，仍存在）
- **现象**：鞋任务 `steps` 出现两个 `V1.0_1`
- **改良**：归档 tip 时按版本内全局序号递增，禁止复用已占用 label

### 2. 非 tip 开新版本体验不稳（验收缺口）
- **现象**：从画布「引用修改」默认 tip，容易误测成「续写」；历史步骤图入口不够显眼
- **改良**：聊天历史每张结果固定「引用」；非 tip 引用时系统消息明确「将开新版本 Vn」

### 3. 品类识别偏关键词（边界风险）
- **现象**：依赖鞋/包/衣等词；「夏季促销海报」等无品类词不会触发隔离
- **改良**：结合快捷参数品类 + 轻量意图分类；无法识别时弹确认「是否新开任务」

### 4. 品牌拦截仅客户端词表（安全仍不足）
- **现象**：改写为「勾形标志跑鞋」可能绕过；优化模型仍可能主动加品牌元素
- **改良**：服务端拦截 + 优化阶段禁品牌约束；结果侧 Logo 检测（人工抽检规则写进验收）

### 5. 测试集用例不合理（建议改测试集，非代码）
| 用例 | 为何不合理 | 建议 |
|---|---|---|
| 同任务串多品类（鞋→衣→包） | 与真实运营「一任务一品」冲突，且易被 adjust 污染 | 改为「一品类一任务」；串品类测「应新开任务」 |
| G-01 要求生成 Nike Logo | 合规上应拦截，不应作为「效果通过」项 | 改为「输入品牌应拦截」负向用例 |
| 默认个人提示词含「以上传图片」却用于文生验收 | 文生/图生混用同一模板，验收口径混乱 | 文生/图生分模板，或验收时分窗分模板 |
| 多用例挤在同一对话（R1） | 额度浪费且结论不可归因 | 强制矩阵：品类 × 类型 × 单意图 |

### 6. 任务标题弱可读
- **现象**：多任务都叫「创意图 · 创意图」，排查痕迹靠消息前缀
- **改良**：用首条用户意图/品类自动命名任务标题（如「鞋履·文生·A-02」）

## 结论

**R2 有条件通过**：P0（类型锁定、品牌拦截、品类自动分窗、文生提示词适配）已验证；图生图与文生图均有独立窗口痕迹。  
剩余主要为版本步骤标签、非 tip 引导与安全纵深，见上表改良方案。

### 关于「点击生图失败」

服务端日志曾出现两类失败：
1. `请输入 1 到 5000 字的生成描述` → 描述为空（现前端会直接提示）
2. `生图请求失败` + `TypeError` → 上游/网络瞬时异常（现会带失败细节，可重试）
